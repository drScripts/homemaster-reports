Executive Summary

Prior to TS-266, when customers asked Helen whether a specific cleaner was available (e.g., "Is Chan available on Saturday morning?"), Helen's tool interface dropped the cleaner name constraint because check_availability and find_next_availability did not declare or forward cleaner_name. As a result, Helen received general slots from other cleaners, and without metadata explaining cleaner availability, could fabricate that the named cleaner was free or confuse customers by quoting another cleaner's slot without consent.

TS-266 resolves this end-to-end:

  • Exposes cleaner_name on check_availability and find_next_availability in tool schemas and execution routers.
  • Resolves the provider by name fragment and customer postal code via findProviderByName, verifying active status and service coverage.
  • Passes the resolved providerId down to the underlying SQL RPC get_available_start_times which already enforces Rule G travel buffers, calendar off-days, and existing sessions.
  • Returns structured provider identity and constraint metadata (searched_provider_id, searched_provider_name, provider_available, provider_unavailable, and explanatory messages for out-of-radius or no slots).
  • Adds clear Step-2 prompt steering and Helen Knowledge SOP rules instructing Helen to never substitute another cleaner's slots without explicit customer consent.
